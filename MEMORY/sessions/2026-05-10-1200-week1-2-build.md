# Session: Week 1-2 Build + WLAA Implementation

Date: 2026-05-10 12:00
Phase: 1 (Week 1-2)

## Goal
Get from seed doc to running platform with admin panel, collections, and frontend.

## What we did
- Initialized git repo, pushed to wfmlabsorg/wfmlabs-hub (public)
- Scaffolded Next.js 15 + Payload CMS 3.84.1
- Fought WSL2/R2 sync performance (node_modules in local dir)
- Attempted Netlify deploy — server actions incompatible with Payload admin
- Switched to Vercel — works correctly
- Debugged blank admin screen — root cause: empty importMap.js
- Fixed build script: `payload generate:importmap && next build`
- Created admin account (ted@wfmlabs.com)
- Built 14 collections total:
  - Identity: Members, Topics, Media
  - Asset types: Papers, Articles, Tools, NewsletterIssues, WikiEntries
  - Cross-cutting: Discussions, AssetVersions, AssetRelationships, AssetContributions, Reactions
- Implemented WLAA base asset fields (_baseAssetFields.ts)
- Built HF-inspired frontend: GlobalNav, Footer, AssetCard, BrowsePageLayout, DetailPageLayout
- Routes for all asset types (browse + detail)
- Theme: HF yellow (#FFD21E), blue links, dark blue-black dark mode

## What we learned
1. Payload importMap.js must be generated, never hand-written
2. Netlify can't handle Payload's server actions — Vercel required
3. WSL2 cloud-synced dirs can't handle large node_modules — use local dev dir
4. Next.js 16 has Turbopack issues on Netlify — stayed on 15
5. Payload generate:types must run after collection changes
6. The WLAA asset architecture document is a strong foundation

- Define detail page UX per asset type (the "Level 2" experience)
- Seed topics taxonomy
- Load initial content (tools, wiki entries)
- Consider the HF-style top nav organization
